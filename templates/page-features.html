1. Dedicated Database & High-Performance Engine

🗄️

27 Dedicated Relational Tables

27 Tables • Zero Postmeta Bloat

Engine:InnoDB / utf8mb4_unicode_ci
Source:includes/Database/Schema.php

Zero Postmeta Bloat

Standard WordPress eCommerce stores execute 40+ JOINs across wp_postmeta per product. OmnifyWP stores each item in a single normalized row, keeping your WordPress database clean.

1 Row per Product View

Impact:Reduces RAM usage per PHP thread to < 15MB

Digital Security

4. Cryptographic Security & Anti-Piracy Delivery

Military-grade HMAC signatures, out-of-webroot binary streaming, and granular download attempt counters.

🔐

HMAC-SHA256 Signed URLs

Every file access URL is cryptographically signed using hash_hmac('sha256') with an internal server salt, user token, file ID, and expiration timestamp. Tampered URLs are immediately rejected.

SHA-256 Tamper Proofing

Service:includes/Downloads/Signed_Url_Service.php
Algorithm:hash_hmac('sha256', $payload, $secret_key)

⏱️

Configurable Expiry & Attempt Caps

Prevent unauthorized link sharing on Discord and forums. Set strict download lifespans (e.g. 48 hours) and maximum attempt limits (e.g. 5 attempts). Once reached, the URL permanently invalidates.

Strict Attempt & Time Limiters

Settings:download_expiry_days, max_downloads_per_item
Per-Product:Granular overrides on individual product files

🛡️

Out-of-Webroot Binary Streaming

Protected files are never stored in public wp-content/uploads/ directories. PHP reads binary chunks into memory and streams headers directly to authorized buyers, masking server file paths.

Zero Direct URL Exposure

Handler:includes/Downloads/Download_Controller.php
Method:readfile() with Content-Disposition: attachment

📜

Forensic IP & User-Agent Audit Trail

Every single file download attempt is logged in wp_omnify_downloads with exact microsecond timestamp, customer ID, IP address, and client user-agent string for forensic DMCA compliance.

Full Forensic Access Ledger

Table:wp_omnify_downloads
Columns:ip_address, user_agent, downloaded_at

🚫

Automated Revocation on Refund

When an order status changes to refunded, disputed, or cancelled, OmnifyWP immediately flips the corresponding record in wp_omnify_customer_access to inactive, revoking download tokens instantly.

Instant Access Invalidation

Table:wp_omnify_customer_access
Status:active → revoked
